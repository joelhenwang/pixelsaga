# Stage 3 Plan: Thirty-Day Memory, Rules, Provider Gateway, Quality

## 1. Context and why this plan exists

Stage 2 is gated and committed (`fcd6ff6`, 355 tests green). The
world completes seven fake days (70 phases, clock at day 8 dawn)
with travel, claims, relationships, training, Director proposals,
deity overrides, roles, and summaries driven through the HTTP
boundary, except for test-fixture setup that injects rows
directly through the unit of work (travel route and location
lookups in `test_s2_gate.py`) — later lanes must keep that
distinction explicit: fixture setup may write rows, but every
behavior under test goes through HTTP. Evidence lives in
`evidence/stage2-seven-day-v1/` (gitignored; regenerated by the
test; `REPORT.md` there is hand-written, not generated).

Two prior framings of Stage 3 disagree, and this plan reconciles
them:

- Session framing: "thirty-day memory, rules, images, quality".
- `backend/README.md` (IMG-FIXTURE section): "provider gateway in
  Stage 3, ComfyUI in Stage 4". `frontend/src/portrait.ts`
  likewise says the provider gateway replaces `portraitFor`.

**Decision: S3 wires provider selection and converts
`portraitFor` to an async cache-reading seam backed by the
existing fixtures; actual generation lands in Stage 4 with
ComfyUI, per the README.** `portraitFor(id): string` is
synchronous and returns a data URI while real generation and
caching are async (`Portrait.vue` already passes a name the
function ignores), so the seam change is a real contract change
that S4 builds on — but no generation work ships in S3.

A second ordering correction: the soak runs **first as a
diagnostic**, not last as a gate. Correction to the earlier
draft: context assembly is *not* unbounded — `application/
context/assembler.py` already ranks candidates and enforces
per-section budgets with truncation, and the Stage 1 context
query takes only 5 observations (though **all** memories for the
owner). Prompt bytes at day 30 may therefore already be near
constant. The real growth vectors are DB and query volume
(every memory row loads every phase), truncation eroding recall
(the budgets silently drop what does not fit), and table
growth. The soak quantifies all three; the memory lane is
designed against the numbers, with its rationale reframed:
**recall under truncation**, not size. This matches the
reference's own posture (`MONOLITH_MIGRATION_REFERENCE.md`,
section 8): no embeddings without a demonstrated recall gap.
The soak's recall probe *is* the recall-gap experiment.

## 2. Goals and non-goals

Goals:

1. Quantify 30-day growth: prompt size, phase wall-time, table
   volumes, query costs, model-call counts (S3-SOAK).
2. Protect recall under truncation with a memory lifecycle:
   salience scoring, promotion to long-term memory, digest
   reads, all provenance-preserving (S3-MEM).
3. Make the model gateway real: wire provider selection
   (OpenRouter adapter exists; composition root is Fake-only),
   generalize retry/fallback semantics, record usage/cost,
   write and execute the keyed live runbook (S3-PROV).
4. Harden actions: a versioned intent schema plus three frozen
   verbs backed by tables that exist (S3-RULE).
5. Record deterministic quality metrics per phase with defined
   denominators; confine LLM-as-judge to the live sample
   (S3-QUAL).
6. Promote through a 30-day gate with the full evidence bundle
   (S3-GATE).

Non-goals (explicitly deferred):

- Image generation, sprites, ComfyUI (Stage 4).
- Embeddings and vector columns/usage, unless the soak's recall
  probe demonstrates a gap that salience plus structured
  retrieval cannot close. (Migration 0001 already enables the
  pgvector extension; the extension itself is not the
  deferred item.)
- Background workers beyond the existing outbox, Temporal,
  WebSockets, multi-machine operation.
- Rewriting the control plane for performance; optimization
  priority stays model inference and context length per the
  reference, section 9.

Live-test convention for all lanes: skip without keys under
`WORLDSIM_LIVE_SCENARIO=1`, following the Stage 1 gate pattern
(`test_stage1_gate.py`); do not copy the Stage 2 test's
assert-absent pattern for new live tests.

Key invariants that must survive Stage 3 (from Stages 1–2):

- LLMs propose; code decides. No model output mutates state
  without validator/resolver approval.
- Perspective isolation: B-scope facts only; beliefs
  holder-or-watcher; hooks/arcs director-side.
- Commit idempotency: `derive_run_id`, tick/seal/commit,
  replay returns duplicates.
- No remote calls inside a database transaction.
- Raw observations/memories are never rewritten by
  summarization or compaction — derived rows reference
  sources, sources stay immutable (S3-MEM must make that
  immutability testable; currently no hash or append-only
  constraint exists on perception rows).

## 5. Lane specifications

### S3-SOAK-001 — Thirty-day diagnostic soak

**Purpose.** Produce the numbers every later lane designs
against. No new features.

**Work.**

1. Run one canonical single-world 300-index scenario with
   scripted fakes on the stage0 seed (two characters waiting,
   one party begun, one companion recruited), mirroring
   `test_s2_gate.py`. State explicitly whether each step goes
   through HTTP (`POST /api/v1/stage1/advance`, as the S2 gate
   does) or the direct orchestrator (`advance_days`); the
   canonical run uses HTTP so the boundary stays under test.
   Week-chunked fixtures with fresh worlds are supplemental
   only — they cannot prove cumulative continuity or recall.
2. Instrument per phase into `evidence/stage3-soak-v1/`:
   prompt bytes per role, phase wall seconds, per-table row
   counts sampled every 10 phases, model-call counts, quiet
   ratio, fallback rate, and context-manifest
   include/exclude counts per section (the assembler already
   records these — the soak surfaces truncation volume).
3. Add the **recall probe**, defined against actual assembly:
   in the opening phases Wren communicates the distinctive
   topic "the north bridge is cursed" to Ash. Resolver effect
   facts never become observation or memory rows (they feed
   narration), so the probe must ride intent-derived content:
   the attempt fact and the "Wren remembers: …" memory
   summary. On day 29 the audit finds the probe memory row,
   then scans day-29 manifests for its source ID and records
   included, excluded-by-budget, or absent, plus a phases-3-5
   baseline proving the probe entered assembly at all. Claims
   and beliefs are *not* assembly candidates, so the probe
   must not plant them.
4. Keep wall-time practical: the 7-day gate runs about 100s
   (96.7s in the generated `scenario.json` vs 104.8s in the
   hand-written REPORT — run-to-run variance is unrecorded,
   so treat both as approximate); 300 phases should land
   under ~10 minutes or the lane reports why before
   proceeding.

**Acceptance.** `evidence/stage3-soak-v1/` contains
`scenario.json`, `growth.json` (per-phase sizes, times,
manifest truncation counts), `tables.json` (row-count series),
`recall.json` (probe result with the include/exclude verdict),
and a `README.md` with four headline numbers: prompt bytes day
30 vs day 1, p50/p95 phase seconds, fastest-growing table,
recall verdict. No thresholds — this lane reports, it does
not gate.

### S3-MEM-001 — Memory lifecycle (recall under truncation)

**Purpose.** Keep the right facts surviving the assembler's
budgets as the world ages.

**Work.**

1. Migration `0019_s3_salience`: `salience` score on
   observations/memories from deterministic inputs only —
   recency decay, effect linkage (rows cited by resolutions or
   claims), owner interaction counts. Scoring is computed by
   code inside the existing commit; weights live in world
   config beside the `model.max_calls_per_phase` precedent.
   Freeze in this lane whether salience is persisted per row
   or derived at query time, and define the interaction-count
   source exactly.
2. Migration `0020_s3_digests`: `long_term_memory` rows holding
   promoted source IDs plus a derived digest. Promotion runs
   as a new orchestrator step after the seal (like the
   Director step): deterministic midnight trigger,
   code-scored candidates, digest text proposed by the
   summarizer role through the existing proposal/citation
   validation. Counts as extra model calls — budget and cost
   them in S3-PROV's accounting.
3. Source immutability: add a content hash and an append-only
   constraint (or documented equivalent) to perception rows so
   "every digest source ID resolves to an unmodified row" is
   mechanically auditable. Backfill existing rows in the
   migration.
4. Retrieval: assembly takes the recent window plus promoted
   digests; ranking consumes salience. Stays structured
   (recency + salience + FTS only if the soak shows a
   text-search gap). Embeddings require a second recall probe
   demonstrating failure after salience ships.
5. Digest reads: decide in this lane whether digests reuse the
   `summary.v1` contract or get their own, and ship the
   matching API + `DiaryView` rendering — a digest no player
   can read is write-only theater.
6. Rollback: a world-config flag disables promotion (reads
   fall back to the S2 window); the flag and its behavior are
   tested, not documented-only.

**Acceptance.** The day-29 recall probe passes on the soak
scenario; prompt bytes at day 30 stay within a multiple of day
1 fixed from S3-SOAK numbers with written justification — if
the soak shows prompts already near-constant under the
assembler budgets, the multiple is recorded as observed and
the binding acceptance becomes recall plus query cost;
the immutability audit passes; digest reads render in the
diary; promotion-off fallback tested; tests follow the
characterization pattern (fake routes, no live calls).

**Example.** A day-4 observation cited in a claim scores above
the promotion threshold at the next midnight run; the digest
"On day 4 Wren claimed the mill is haunted (sources …)"
enters `long_term_memory`; day-29 assembly for Wren includes
the digest, not the raw row.

### S3-PROV-001 — Provider selection, cost, live runbook

**Purpose.** Make the gateway real; it already exists as an
adapter, so this lane wires, generalizes, accounts, and proves.

**Work.**

1. Wire provider selection in the composition root
   (`interfaces/http/state.py`): profile-driven choice
   between `FakeGateway` and `OpenRouterGateway`. No call-site
   branching; the port contract does not change.
2. Generalize retry/fallback semantics: the adapter handles
   rate-limit `retry-after` and timeouts today
   (`test_model_gateway.py`); define the full policy
   (which errors retry, bounds, what the orchestrator sees,
   how degradation matches the existing quiet/fallback path)
   and test the gaps.
3. Usage/cost schema: `ModelCall` holds tokens only. Add the
   companion cost record with provider pricing version and
   fallback rules (providers that do not report usage get
   byte-based estimates, labeled as such). No live call ships
   without a cost row.
4. Portrait seam: convert `portraitFor` to an async
   cache-reading seam backed by fixtures (the name parameter
   must actually participate — today it is ignored). No
   generation; S4 owns that.
5. Write the keyed live runbook (`docs/LIVE_RUNBOOK.md`):
   required env keys, spend caps, the bounded sample (fixed
   world, fixed phases, which roles go live), capture
   procedure. Then **execute it once**; commit the bundle
   under `evidence/stage3-live-v1/` with a matching `.gitignore`
   exception (`evidence/` stays ignored otherwise).

**Acceptance.** Real-endpoint sample serves at least narrator
and decision roles; every live call has usage + cost rows; the
runbook exists and was demonstrably followed (bundle
committed); CI passes with `WORLDSIM_LIVE_SCENARIO` unset.

### S3-RULE-001 — Versioned intents and three frozen verbs

**Purpose.** Harden actions without churning every fixture on
each new verb.

**Work.**

1. Prerequisite — close the role-enforcement gap: several
   mutating routes (`claims`, and reportedly `progress` and
   `relationships`) read the raw `X-Worldsim-Role` header
   instead of going through `require_role`, so "roles
   server-enforced" is not true of every caller today. This
   lane server-enforces and tests every mutating route
   before the gate asserts it; any route deliberately left
   header-bound is named in `backend/README.md` with its
   reason.
2. Version the decision contract at the command level
   (`user_command.schema_version`, since `character_intent`
   carries no version): v2 schema accepts the v1 families
   plus the three verbs below. The prompt file becomes
   `character_decision.v2.md`; v1 stays valid until every
   caller migrates, then is removed **in this lane** (clean
   cutover, no shims).
3. Exactly three verbs, all backed by existing tables:
   - `spar`: a training-bout verb resolving through the D&D
     engine against live HP pools (damage, saves, conditions
     per the DND-COMBAT rules; no XP — none exists yet).
   - `appeal`: files a claim through the knowledge path with
     audience rules (speaker holds, audience hears by
     position), reusing `commands/knowledge.py` validation.
   - `give`: transfers an `item_instance` through
     `give_item`/`transfer_item` with ownership and location
     checks (parties share scenes, so co-location is the
     permission rule; record it).
   No candidate lists, no substitutions: these three or the
   lane is rescoped in writing before implementation.
4. Each verb follows the typed write path with validator
   tests (permission/knowledge/location/version rejections)
   and seeded resolver tests. Update the TypeAdapter route,
   the generated `content/clients/worldsim.ts`/OpenAPI, the
   frontend API client, `SceneView.vue` (which today offers
   only the five old families), and `verify.mjs` (which
   exercises the old action) — the lane is API **and** UI,
   not API-only.

**Acceptance.** v2 documented in `backend/README.md`; v1
removed with all callers migrated (including every fake
route); each verb has rejection + determinism tests; client
types regenerated; `verify.mjs` exercises a v2 verb end to
end and stays green.

### S3-QUAL-001 — Deterministic quality metrics

**Purpose.** Say something about text quality that restraint
metrics cannot, without flaky judges in CI.

**Work.**

1. Compute per-phase metrics from committed rows only (no
   extra model calls), each with a frozen
   definition — window, denominator, normalization:
   narration repetition rate (normalized duplicate n-grams
   over the phase's beats, n fixed), beat diversity
   (distinct cited-fact keys per scene over scenes),
   fallback rate (fallback scenes over scenes), quiet ratio
   (quiet phases over phases), Director acceptance
   (accepted proposals over runs).
2. Baselines need durable history: evidence bundles are
   gitignored, so commit the baseline rollups (7-day rerun +
   30-day soak numbers) as versioned JSON under `docs/` (or
   an equivalent committed location) — otherwise "compare
   against history" is unreviewable.
3. Live-sample judge protocol for the S3-PROV sample: fixed
   rubric (continuity, perspective discipline, trope
   avoidance), sampled phases fixed in advance, human review
   recorded in the bundle. The judge may be LLM-assisted but
   the record is human-signed; signing is a process step, not
   a pytest assertion.

**Acceptance.** Metrics computed for both reruns with
committed baseline JSON; rubric document exists; judgments
recorded for the S3-PROV sample.

### S3-GATE-001 — Thirty-day promotion

**Purpose.** The same bar as prior gates, at thirty days —
with pytest assertions and CI evidence kept distinct.

**Work.** `backend/tests/test_s3_gate.py` runs the 30-day
scenario with lane interventions through HTTP (promotion
visible, v2 verbs exercised, provider selection on fakes),
asserts the in-test items below, and writes
`evidence/stage3-thirty-day-v1/` following the S2 bundle
pattern (`scenario`, `consistency`, `perspective`, `quality`,
`budget`, `performance`, `recovery`, `accessibility`,
`migration`, `security`, `index`, plus hand-written
`REPORT.md`).

Asserted in-test (mechanical, unfalsifiable wording banned —
every threshold below is frozen here, not at runtime):
- Roles server-enforced on every mutating route (gap closed as
  the S3-RULE prerequisite); wrong-role commands 403, tested
  per route, not sampled.
- 300 consecutive advances complete on one world; clock at day
  31 dawn.
- Prompt bytes at day 30 within the S3-MEM multiple of day 1.
- Day-29 recall probe passes (include verdict, not
  absent-or-excluded).
- Positional claim divergence holds (speaker vs distant
  holder, as in S2).
- A 3-phase travel leg completes; a 2-phase training session
  lands progress 8; relationship evidence stays directional.
- Replays at three phases (early, mid, final) return
  duplicates — single-phase replay is insufficient at this
  scale.
- Digests keep perspective and provenance; immutability audit
  passes.
- Injected pre-narration crash resumes with no missing or
  duplicate scenes.

Recorded as CI evidence alongside the test (not inside it):
`verify.mjs` green, ruff/format/basedpyright clean, full suite
green, secret-leak probes, migration head. The S3-PROV live
bundle is referenced, not re-run.

## 6. Execution conventions (binding on every lane)

- Plan before files on multi-file work; todo list per lane
  (`S3-Soak`, `S3-Mem`, …), batched with real calls.
- Research before editing: reuse existing patterns; run `lsp
  references` before modifying exported symbols.
- Fix source, never suppress symptoms; clean cutover — every
  caller migrated, no shims/aliases/deprecated paths left.
- Verification per the repo standard: bug fix → reproduce,
  fix, confirm; feature → throwaway script proof, permanent
  tests only for genuinely uncertain edges; UI → `verify.mjs`
  plus screenshots.
- Static gates every lane: ruff, ruff format, basedpyright,
  full pytest. Commit per lane with the lane ID in the
  message. Update `backend/README.md` in the same commit as
  the behavior it documents.
- Evidence bundles are gitignored and regenerated by their
  tests, except the executed live bundle and the QUAL
  baselines, which commit via explicit exceptions.

## 7. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| 30-day suite too slow for CI | Canonical single-world run stays the promotion proof; week-chunked fixtures supplement locally; continuity asserted on seams |
| Salience becomes opaque tuning | Deterministic inputs, weights in world config, recall probe passes or the lane does not ship; promotion has a tested off-flag |
| Promotion adds model calls and cost | Digest calls budgeted under the existing per-phase budget and costed in S3-PROV accounting |
| Provider costs surprise | Spend caps in the runbook; cost rows before the first live call; bounded sample |
| v2 migration stalls halfway | v1 removal is acceptance, not follow-up; one lane owns the cutover including UI and generated clients |
| Embeddings pressure without evidence | The recall probe is the only promotion criterion; structured retrieval is the default |
| Metrics become vanity charts | Frozen definitions, committed baselines, no gates on values until two runs of history; the recall probe and hard invariants decide |
| Raw DB/query growth (all-memories load) | Soak quantifies; salience-indexed queries and pagination are the fix, not wider budgets |
| Migration backfill and index cost | Backfill in-migration with row-count logging; add indexes beside the queries they serve, named in the lane |
| Secrets in prompts or evidence | Secret-leak probes stay in CI; live bundle reviewed for key/proposition leakage before commit |
| Provider rate limits and outages | Retry/fallback policy tested; degradation matches the existing quiet/fallback path |
